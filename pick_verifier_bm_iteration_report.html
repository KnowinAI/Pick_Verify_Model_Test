Pick Verifier BM 构建与模型迭代报告

本报告说明 BM v1 稳定后应该怎么用、后续模型如何演进、测试集如何抽样，以及为什么不能把测试集当训练集直接使用。

面向：抓取结果 VLM 评估 核心：稳定 BM + 样本池迭代 建议：BM v1 冻结，BM v2 独立扩展

一、核心结论

BM v1 不是用来训练模型的，而是用来做稳定评估、回归测试和历史模型对比。

BM v1 一旦冻结，就不要随便增删改样本。新数据、新难例、新类别应进入样本池或 BM v2，而不是直接塞回 BM v1。

稳定尺子对比模型是否真的进步

所有模型版本都跑同一批 BM v1，才能比较 base、opt1、opt2、opt10 的结果是否可比。

回归测试防止新模型退化

新模型在难例上提升时，可能把原来会的普通场景学坏。BM v1 用来检查基础能力是否退化。

汇报基准让结果可信

对同事或团队汇报时，可以说明所有模型都在同一版冻结 BM 上测试，结果更可信。

二、BM v1 要不要永远不变？

BM v1 不需要成为唯一测试集，但 BM v1 本身要保持稳定。

问题 建议做法 原因
BM v1 能不能继续用很多轮？ 可以，建议长期保留。 它是基础能力和历史模型对比的稳定基准。
发现新难例要不要加入 BM v1？ 不要直接加入，应进入样本池或 BM v2 候选池。 直接加入会破坏历史分数可比性。
发现 BM v1 标签错了怎么办？ 可以修，但要升版本并记录原因，例如 BM_v1.1。 只允许修正客观错误，不允许为了模型表现调整 BM。
BM v1 样本能不能拿去训练？ 原则上不要。 否则模型会“背题”，BM 分数会虚高。
重要原则：不为模型表现修改 BM，只为修正客观错误修改 BM。

三、推荐的数据分层

建议把数据分成四层，不要把所有图片都混成一个目录。

样本池 Pool

持续进入的新图片和历史图片。可以不断增加、标注、清洗。它是训练集、候选集和后续 BM 的来源。

Failure Pool

当前模型预测错误的样本集合。用于分析模型短板，并指导下一轮采样和训练。

BM v1 Basic

基础稳定集，冻结后长期不变。主要用于基础能力、整体准确率和回归测试。

BM v2 Hard

从新数据和失败样本中抽取的新冻结集。用于评估新增难例、新类别、新场景能力。

样本池 pool：持续新增、持续标注、持续清洗 BM_v1_basic：冻结基础集，用于长期对比 failure_pool：当前模型错例池，用于指导下一轮训练 BM_v2_hard：新冻结难例集，用于评估新能力

四、后续模型应该怎么演进？

模型迭代不要围绕“调一次、看几张图”进行，而应该形成闭环。

1. 固定 BM冻结 BM v1，确保人工标签和样本 ID 稳定。
2. 跑当前模型base、opt10、opt11 都跑同一版 BM。
3. 分析错例按物体类别、夹取关系、背景、深度等维度归因。
4. 补充训练数据从样本池找相似样本，不直接拿 BM 训练。
5. 再评估新模型再次跑 BM v1 和新增 BM，比较提升与退化。

推荐闭环

BM v1 跑分 → 找错例 → 分析错误类型 → 从样本池找相似样本训练 → 训练新模型 → 再跑 BM v1 → 检查提升和退化

这个流程的关键是：BM 告诉你模型哪里错，但不要把 BM 直接喂给模型训练。

五、BM v1、BM v2 和 BM All 的关系

推荐不要把所有样本都揉成一个总分，而是分开看基础能力和难例能力。

集合 定位 是否冻结 主要用途
BM_v1_basic 基础稳定集 冻结 长期回归测试、基础能力对比
BM_v2_hard 新增难例集 冻结 评估模型对新难例、新类别、新场景的能力
BM_all 综合报告集 由多个冻结 BM 汇总 对外给一个综合结果，但内部仍要看分项

示例报告口径

模型版本 BM v1 基础集 BM v2 难例集 综合结果 解读
base 78% 52% 68% 基础可用，难例较弱。
opt10 86% 61% 76% 基础明显提升，难例略有提升。
opt11 84% 70% 78% 难例提升明显，但基础集略有回退，需要看是否可接受。

六、测试集应该怎么抽？

抽样建议分三层：主标签硬平衡、物体类别硬平衡、难例标签软覆盖。

第一层：G/N 主标签硬平衡

正式 BM 里不要全是抓住，也不要全是没抓住。比如 BM v1 做 300 张，可以设置：

G：150 张 N：150 张

第二层：物体类别硬平衡

如果当前主要物体类别是 5 类，可以按每类固定数量抽取：

物体类别 总数 G N

第三层：难例标签软覆盖

下面这些维度不要全部做硬组合，否则组合会爆炸。建议只要求覆盖到一定数量。

维度 建议覆盖要求 说明
透明/半透明不少于 30 张透明手机壳、玻璃杯等容易造成误判。
高反光不少于 30 张屏幕、玻璃、金属物体可作为重点覆盖。
浅夹不少于 40 张浅夹与边缘接触常耦合，是模型难点。
夹爪近桌/抵桌不少于 30 张容易把桌面支撑误判为抓住。
复杂背景/低对比不少于 40 张纹理桌布、文字密集、背景杂乱都可能干扰。
细长物体不少于 50 张筷子、笔、尺子等需要重点看对准未接触和浅夹。

七、BM v1 和 BM v2 的抽样定位

BM v1基础稳定集

  • 目标不是最难，而是可靠、稳定、可复现。
  • 覆盖主要物体类别。
  • G/N 尽量平衡。
  • 人工标签明确。
  • 不要放太多极端模糊、严重遮挡、无法判断样本。

BM v2新增难例集

  • 围绕当前模型错得多的场景抽。
  • 可包含透明、反光、浅夹、近桌、复杂背景等难例。
  • 建议从 failure_pool 和新样本中抽。
  • 不要替代 BM v1，而是和 BM v1 一起看。

BM v2 示例配比

来源 数量示例 目的
模型失败样本100 张覆盖当前模型真实短板。
新增难例样本70 张覆盖新物体、新背景、新夹取形态。
普通稳定样本30 张防止 BM v2 过于极端，保留少量正常场景。

九、推荐执行方案

阶段 要做什么 产出
阶段 1：整理样本池 统一 cam0/cam1 组对、生成样本 ID、去除坏组。 pool manifest、样本标注总表。
阶段 2：人工标注 标 G/N、细分抓取状态、空间关系、背景、有效性。 带人工真值的样本池。
阶段 3：冻结 BM v1 按 G/N 和物体类别硬平衡，按难例标签软覆盖抽样。 BM_v1_basic。
阶段 4：模型评估 base 和当前模型都跑 BM v1，记录预测和错误方向。 模型对比报告、failure_pool。
阶段 5：训练迭代 根据错例类型从样本池补充训练数据，训练新模型。 opt 新版本模型。
阶段 6：新增 BM 积累新难例后冻结 BM v2，与 BM v1 一起测试。 BM_v2_hard、BM_all 综合报告。

十、最终建议

当前最合理的策略是：先做一个可靠的 BM v1，不追求一次性覆盖所有极端场景；后续用 failure_pool 和 BM v2 逐步推进难例能力。

一句话总结：BM v1 负责“稳定比较”，failure_pool 负责“发现问题”，训练集负责“解决问题”，BM v2 负责“验证新问题是否解决”。
  • BM v1 冻结后不要随便改，作为基础能力和回归测试基准。
  • 模型错例不要直接拿 BM 训练，优先从样本池找相似样本训练。
  • 新难例不要塞回 BM v1，应进入 BM v2 或后续版本。
  • 每次模型报告同时看 BM v1、BM v2 和综合结果，不只看一个总分。
  • 测试集抽样采用：G/N 硬平衡、物体类别硬平衡、难例标签软覆盖。
