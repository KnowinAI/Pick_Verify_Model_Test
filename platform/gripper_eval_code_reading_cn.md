# 夹爪评估平台代码解读

## 一句话概括

这份 JS 是一个 Node.js 后端服务，用来管理机器人夹爪图片评估流程。它负责读取和保存图片记录，调用视觉语言模型判断是否夹住物体，接收人工标注，计算统计指标，并提供前端页面和 API。

## 核心数据

- 数据文件：`gripper_eval_data.json`
- 前端页面：`gripper_eval.html`
- 本地图片目录：`local_images`
- 远程源服务：默认 `SOURCE_BASE_URL`
- VLM 服务：默认 `VLM_ENDPOINT`

## 主流程

1. 服务启动后监听 `PORT`，默认是 `5034`。
2. 访问 `/` 或 `/gripper_eval.html` 返回评估平台页面。
3. 前端通过 `/api/records` 获取图片记录和统计结果。
4. 图片可以来自本地目录、上传接口、实时相机，或远程源服务。
5. 系统调用 VLM，要求模型判断夹爪是否夹住物体。
6. 人工通过标注接口保存结果。
7. 代码会把模型结果和人工结果比较，生成正确、漏判、误判等分类。
8. 最后统计准确率、召回率、精确率、漏判率和误判率。

## 主要模块

| 模块 | 作用 |
| --- | --- |
| 配置区 | 设置端口、远程服务、VLM 地址、数据文件路径和图片目录 |
| 数据读写 | 读取和写入 `gripper_eval_data.json` |
| 本地图片同步 | 扫描 `local_images`，把图片变成评估记录 |
| 远程数据合并 | 从 5022 源服务拉取 records，并与本地标注合并 |
| VLM 推理 | 把图片转成 base64，调用 VLM，解析 G/N 或中文输出 |
| 人工标注 | 保存 human_result、归因原因、备注和物体标签 |
| 统计分析 | 计算准确率、召回率、精确率、漏判率和误判率 |
| 实时相机 | 从 5033 或 9002 服务抓图，保存为本地记录 |
| HTTP API | 给前端提供记录查询、上传、删除、标注、VLM 推理等接口 |

## 重要接口

| 接口 | 方法 | 作用 |
| --- | --- | --- |
| `/api/records` | GET | 获取记录列表和统计摘要 |
| `/api/reviews` | GET | 获取评估记录列表 |
| `/api/reviews/:id` | GET | 获取单条记录 |
| `/api/upload-image` | POST | 上传 base64 图片并触发 VLM |
| `/api/reviews` | POST | 兼容 reviews 格式上传图片 |
| `/api/vlm/:id` | POST | 对单条记录执行 VLM 推理 |
| `/api/vlm/auto-start` | POST | 批量补齐 VLM 推理 |
| `/api/vlm/auto-status` | GET | 查看批量 VLM 任务进度 |
| `/api/annotations/:id` | POST | 保存人工标注 |
| `/api/realtime/save` | POST | 从实时相机保存一组图片 |
| `/api/local-images/:name` | GET | 读取本地图片 |
| `/api/custom-reasons` | GET/POST/DELETE | 管理自定义归因原因 |
| `/api/import-legacy` | POST | 导入旧平台数据 |

## 评估分类逻辑

模型输出会被统一成二分类结果。

- `grasped` 表示夹住
- `not_grasped` 表示没夹住
- `no_result` 表示没有可用模型结果

人工标注和模型结果比较后，会得到这些分类。

- 正确识别夹住
- 正确识别未夹住
- 漏判
- 误判
- VLM 调用失败
- 待人工标注
- 无效样本
- 无法判断

## 注意点

1. 服务默认监听 `0.0.0.0`。如果部署在局域网或公网，建议加鉴权。
2. 上传接口读取完整 base64 请求体，没有明显的大小限制。图片过大时可能占用较多内存。
3. VLM 和源服务地址里有默认 IP，换环境时最好通过环境变量配置。
4. 批量 VLM 是用进程内对象记录状态，服务重启后任务状态会丢失。
5. 本地数据文件是 JSON 文件，并发写入多时可能需要更稳的存储方式。
