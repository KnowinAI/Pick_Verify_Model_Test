1这个项目是做什么的

核心要解决一个问题：给一张「机器人夹爪 + 物体」的照片，判断到底有没有夹住，并持续衡量视觉模型（VLM）判断得准不准。

它不只是跑一个模型看准确率，而是搭了一套 可追溯的模型测试台账：测试集、人工标注、模型预测、具体图片、准召率指标全部串起来，支持回归测试、版本对比和历史追溯。

G = 夹住 (Grasped)   N = 没夹住 (Not Grasped)

2怎么跑起来 / 给同事用

  • 双击 start_lan_5034.bat 即可启动，固定端口 5034。
  • 启动脚本自动：杀掉占用端口的旧进程 → 探测本机局域网 IP → 打开浏览器。
  • 本机访问 http://127.0.0.1:5034/，同事访问 http://<本机局域网IP>:5034/（需放行 Windows 防火墙入站 TCP 5034）。
  • 后端入口 platform/gripper_eval_server.js，约 3600 行，原生 http 模块手写路由，零外部依赖。
  • 根路径 / 自动重定向到样本池 /pool；旧的 gripper_eval.html 一体化工作台已退役，职责拆分到下面几个页面。

6最关键的设计：四层台账

这是整个项目的灵魂。

样本层
图片 + 人工标准答案 + 属性标签。一条 = 一组 cam0/cam1。
BM 层
某个测试集版本固定包含哪些样本（冻结），作为回归/对比基准。
运行层
某个模型在某个 BM 上跑了一次 = 一个 run，记录模型、prompt、时间。
预测层
这次 run 里每张样本预测成什么、对不对、原始输出是什么。
核心铁律：模型结果只追加，不覆盖样本表。
样本表 = 标准答案（人工标注 + 属性）；模型结果表 = 历史答题记录（每次 run 独立存）。
这样历史结果永远不会丢，可随时回看「base / opt10 / opt11 各自当时预测成什么」。

7标签体系详解（样本层的核心）

所有标签由单一数据源 platform/annotation_schema.js 定义：改一处，后端存储白名单、标注表单、BM 筛选三处同时生效。标签分 6 组。

结论（必填）

字段选项说明
human_result 人工结果 必填夹住 / 未夹住唯一必填项，对应 G / N，是评测的标准答案

夹取关系（每张都看）

字段选项
夹爪状态张开 / 闭合 / 半闭合 / 不清楚
夹爪张开大小张开大 / 张开小
夹爪-物体关系错位空抓 / 对准未接触 / 部分包围 / 充分包围 / 看不清
夹爪-桌面关系离桌 / 近桌未接触 / 接触桌面 / 抵住桌面 / 隔物支撑 / 看不清
夹取深度 / 角度浅·中·深·未进入 ／ 正夹·侧夹·斜夹
遮挡程度无遮挡 / 部分遮挡 / 严重遮挡

这组是模型出错归因的关键维度——可以分析「对准未接触」「抵住桌面」这类难例上模型的表现。

物体属性（字典默认 · 一般不用改）

物品名称、透明度、反光程度、形变属性、几何结构、材质。这些是 物体级属性（dict:true），由 object_dictionary.json 按类别自动带默认值，省去重复标注。例如打开一张 PhoneCover：

// object_dictionary.json 自动带入
PhoneCover → 手机壳 · 不透明 · 中等反光 · 可形变 · [薄片] · [塑料]

个别不符的样本可在页面直接改写后保存，不影响字典。

场景（可选）与 复核

  • 背景复杂度：干净 / 复杂 / 低对比 / 反光背景 / 杂乱。
  • 物品颜色（多选）：黑色/深色、与桌面颜色相近、与夹爪颜色相近…… 用于分析「同色边界」对分割的影响。
  • 复核状态 bm_review_status：pending / approved / rejected —— 这一项决定能否进入「仅复核通过」的 BM。
  • 备注：自由文本。
字段三种类型： select 单选 multi 多选标签 text 自由文本。 想加新标签，最常见就是复制一行 select，改 key / label / options 放进合适分组即可，三处自动生效。

8如何确认 / 冻结一个 BM 快照

BM（Benchmark）= 一份固定的测试集版本。在 /bm 页面操作，产物写到 eval_registry/bm/<bm_id>/，全程只读样本池和标注，绝不动原图。

第 1 步：看标注进度

页面顶部按类别显示「总数 / 已标注 / G / N / 复核通过」。只有 human_result 已填的样本才算「已标注」，才有资格进 BM。

第 2 步：选一种冻结方式

方式 A · 自动配额抽样

  • 每类数量：如填 50 = 每个类别抽 50（留空 = 全部已标注）
  • G/N 尽量均衡：每类内夹住/没夹住对半抽
  • 仅纳入复核通过：只要 approved 的样本
  • 随机种子 seed：同 seed 抽样结果完全一致 → 可复现

方式 B · 手动挑选

从「大水池」用筛选条件逐个勾选样本，按挑选顺序冻结、自动去重。适合精确控制测试集内容、构造特定难例集。

第 3 步：冻结（每条样本连同当时的标注一起写死）

eval_registry/bm/<bm_id>/
  snapshot.jsonl   # 每行一条样本：sample_id、cam0/cam1 路径、cam1_sha1、
                   #   当时的全部标注、annotation_operator、frozen_at（冻结时刻）
  meta.json        # bm_id、criteria（抽样条件+seed）、total、G/N 计数、按类别计数
「确认」的本质 = 冻结。 快照把每条样本的标注复制一份固化下来。之后即使原样本标注被修改，这个 BM 里的标准答案也不变 —— 保证历史评测口径稳定、可对比。

第 4 步：锁定（防误删基准）

操作说明
添加样本向未锁定的快照追加样本（按 sample_id 去重，已锁定拒绝）
🔒 锁定 / 解锁锁定后禁止删除和追加，作为正式基准保护起来
删除整目录移除（已锁定会被后端拒绝，需先解锁）
配套规则： BM 冻结后样本 ID / 图片 / 人工标签都不变；若要修正标签，建议生成新版本（如 BM_v1.1），而不是改动旧 BM。这样每次模型评测（run）都跑在一个确定、可复现、被锁定保护的基准上。

9评测指标怎么算（口径统一）

按「夹住 / 没夹住」二分类算混淆矩阵：

预测：夹住预测：没夹住
真实：夹住TP 正确FN 漏判
真实：没夹住FP 误判TN 正确
 
总准确率   = (TP+TN) / 全部已计分样本
夹住精准率 = TP / (TP+FP)
夹住召回率 = TP / (TP+FN)
没夹住精准率 = TN / (TN+FN)
没夹住召回率 = TN / (TN+FP)

每个指标都能 下钻到具体样本和图片，不是孤立数字。错误还分方向：G_to_N 漏判抓住 N_to_G 误判抓住。

已有真实 run 示例： 模型 pick_verifier_1200_merged 在 BM-v1（16 样本）上 —— 准确率 93.75%、夹住精准率 1.00、夹住召回率 0.90、没夹住召回率 1.00。

10模型评测怎么跑

  • 模型注册在 eval_registry/models.json，新增版本只加一项即可。
  • 当前线上模型 pick_verifier_1200_merged，走 VLM HTTP 接口，输出协议二分类 G / N。
  • 一次 run 把每条样本预测落到 eval_registry/runs/<run_id>/（meta.json + predictions.jsonl），并自动算准召率。
  • 关键约束：跑 run 只读 BM 快照和图片，绝不动原图和平台标注记录。

11版本对比（模型迭代价值所在）

对比两个 run（如 base vs opt10），系统把样本分成四类：

类型含义用途
improved旧错 → 新对提升样本
regressed旧对 → 新错退化样本（重点关注）
still_wrong都错持续难题
still_correct都对稳定样本
准确率从 78% → 86% 只能说整体变好，看不出「是不是只在 PhoneCover 上涨、却牺牲了 SlenderItems」。版本对比就是为了回答这个。

12工程亮点 / 安全约束

数据安全优先

批量去重/合并/清理先生成副本目录和报告，保留源数据；删除前先确认。

可复现抽样

BM 快照用带 seed 的伪随机，同 seed 抽样结果一致。

标注字段单一数据源

annotation_schema.js 一处定义，后端白名单/表单/筛选三处同时生效。

向后兼容

新旧文件名都能解析，组对优先 capture_group_id，再用时间戳+后缀兜底。

零数据库依赖

纯 JSON/JSONL 文件存储，便于换电脑、归档、复核。

局域网协作

一键启动，多人同时标注审核，支持标注冲突处理。

13可以这样对同事一句话总结

我们做的不是「一个测试集」，而是一套 可追溯的夹爪抓取测试台账：每个 BM 版本固定一批样本和人工标签；每次模型评测生成一个 run，保存每张图的预测、原始输出和对错；准确率召回率都能下钻到具体图片，还能对比不同模型版本哪些变好、哪些退化。整套系统本地一键启动、局域网共享、纯文件存储，数据安全可迁移。
